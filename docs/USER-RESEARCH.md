# User Research — Grammar Quest

> สถานะ: **proto-research** (ยังไม่มีการสัมภาษณ์ผู้ใช้จริง) — ใช้ข้อมูลจากเจ้าของโปรเจกต์ (ผู้ใช้หลัก), เนื้อหาชีทเรียน 14 บท,
> รูปแบบข้อสอบ TOEIC และหลักการเรียนรู้ที่มีงานวิจัยรองรับ. ทุกข้อด้านล่างที่เป็น "สมมติฐาน" ต้องพิสูจน์ด้วย usability test ในหัวข้อท้ายไฟล์.

## 1. เป้าหมายการวิจัย
1. เข้าใจว่าผู้เรียนใช้เวลาเรียนไวยากรณ์เมื่อไร ที่ไหน บนอุปกรณ์อะไร
2. ระบุจุดที่ทำให้เรียนจากชีทกระดาษไม่ได้ผล (pain points)
3. กำหนดสิ่งที่แอปต้องทำให้ได้ เพื่อให้ "ตอบผิดแล้วเข้าใจ" และ "จำได้จนถึงวันสอบ"

## 2. Proto-persona
**"มิว" — นักเรียน ม.4 สายวิทย์ อายุ 15–16 ปี**
- เป้าหมาย: สอบ TOEIC ให้ได้คะแนนดี (เน้น Reading Part 5 Incomplete Sentences และ Part 6 Text Completion ที่วัดไวยากรณ์โดยตรง)
- อุปกรณ์: มือถือ (หลัก, จอ ~390px) + คอมพิวเตอร์ (ทบทวนยาว ๆ ที่บ้าน); ต้องเริ่มบนเครื่องหนึ่งแล้วทำต่อบนอีกเครื่องได้
- ช่วงเวลาเรียน: ช่วงสั้น 5–15 นาที (รอรถ พักเที่ยง ก่อนนอน) และช่วงยาว 30–60 นาทีวันหยุด
- ภาษา: อ่านคำอธิบายไวยากรณ์ภาษาไทยเข้าใจเร็วกว่า; โจทย์และตัวอย่างต้องเป็นภาษาอังกฤษตามข้อสอบจริง
- พฤติกรรม: มีชีท 14 บทแต่ **ไม่มีเฉลย** → ทำแบบฝึกหัดแล้วไม่รู้ว่าถูกไหม และไม่รู้ว่าผิดเพราะอะไร

### Pain points (จากสภาพชีทจริง)
| # | ปัญหา | ผลกระทบ |
|---|-------|---------|
| P1 | ชีทไม่มีเฉลย (อ้าง "Answer key on page 152" แต่ไม่มีหน้า) | ไม่รู้ผลทันที, เรียนรู้ผิดซ้ำ |
| P2 | เฉลยทั่วไปบอกแค่ตัวเลือก ไม่บอกเหตุผล | เดาถูกโดยไม่เข้าใจ, ไปผิดตอนสอบ |
| P3 | กระดาษพกยาก, ทำบนมือถือไม่ได้ | เสียช่วงเวลาสั้น ๆ ที่เรียนได้ |
| P4 | ไม่มีระบบทบทวนข้อที่เคยผิด | ลืมก่อนวันสอบ |
| P5 | แรงจูงใจลดลงเมื่อเรียนคนเดียว | เลิกกลางทาง |

## 3. Jobs To Be Done
- **หลัก:** "เมื่อฉันทำข้อผิด ฉันอยากรู้ทันทีว่าทำไมผิดและกฎคืออะไร เพื่อจะไม่ผิดซ้ำในห้องสอบ"
- "เมื่อมีเวลาว่าง 5 นาที ฉันอยากเปิดแล้วทำต่อจากที่ค้างได้ทันที โดยไม่ต้องหาว่าถึงไหนแล้ว"
- "ก่อนสอบ ฉันอยากทบทวนเฉพาะเรื่องที่ตัวเองยังอ่อน"
- "ฉันอยากเห็นว่าตัวเองก้าวหน้า เพื่อมีแรงเรียนต่อทุกวัน"

## 4. Journey map
| ขั้น | สิ่งที่ทำ | ความคิด/ความรู้สึก | สิ่งที่แอปต้องมี |
|------|-----------|---------------------|-------------------|
| เปิดแอป | เปิดจากไอคอนบนหน้าจอโฮม | "เมื่อวานถึงไหนแล้วนะ" | ปุ่ม "เรียนต่อ" ปุ่มเดียว, streak, หัวใจ |
| อ่านสรุป | อ่านการ์ดสรุป 1–2 นาที | "ขอสั้น ๆ เข้าใจง่าย" | การ์ดสรุปภาษาไทย + ตัวอย่าง + จุดหลอกของ TOEIC |
| ทำข้อ | ตอบทีละข้อ | "ข้อนี้ไม่แน่ใจ" | ตัวเลือกชัด, ปุ่มตรวจคำตอบ, ไม่มีจับเวลาบังคับ |
| อ่านเฉลย | ดูผลทันที | "อ๋อ ผิดเพราะแบบนี้" | เหตุผลไทย, ทำไมตัวที่เลือกผิด, ลิงก์กลับกฎ |
| จบบท | เห็นคะแนน XP | "ได้เพิ่มเยอะ" | สรุปผล + รายการข้อผิดเปิดดูเหตุผลได้ |
| ทบทวน | วันถัดไปทำข้อที่เคยผิด | "จำได้แล้ว" | คลังข้อผิดแบบเว้นระยะ |
| เปลี่ยนเครื่อง | เปิดบนคอม | "ความคืบหน้าต้องตรงกัน" | รหัสซิงก์ / ล็อกอิน Google |

## 5. หลักการเรียนรู้ที่นำมาใช้ (evidence-based)
| หลักการ | การนำไปใช้ในแอป |
|---------|-----------------|
| Retrieval practice (ฝึกดึงความรู้ออกมา) | ทุก lesson เป็นการตอบคำถาม ไม่ใช่อ่านอย่างเดียว |
| Immediate elaborative feedback | เฉลยทันทีหลังตอบ พร้อมเหตุผลและกฎ ไม่ใช่แค่ถูก/ผิด |
| Error correction loop | ข้อที่ผิดถูกนำกลับมาท้าย lesson จนกว่าจะตอบถูก |
| Spaced repetition (Leitner) | คลังข้อผิด 3 กล่อง ทบทวนเมื่อครบกำหนด 0/1/3 วัน |
| Interleaving | โหมด TOEIC Mix สุ่มข้อหลายบทปนกัน เหมือนข้อสอบจริง |
| Worked examples | การ์ดสรุปมีตัวอย่างประโยคและการวิเคราะห์ |
| Mastery / small steps | lesson ละ 8–12 ข้อ จบได้ใน 5–10 นาที |
| Motivation (goal-gradient, streak) | XP, level, streak, progress bar ทุก lesson |

## 6. ข้อกำหนดที่ได้จากงานวิจัย (requirements)
- R1 เฉลยทุกข้อ + เหตุผลภาษาไทย + เหตุผลว่าทำไมตัวลวงผิด (P1, P2)
- R2 ใช้ได้บนมือถือ 320–430px และคอม; ทำงาน offline ได้ (P3)
- R3 คลังข้อผิด + การทบทวนแบบเว้นระยะ (P4)
- R4 XP / Level / Streak / หัวใจ ที่ไม่ลงโทษจนเลิกเรียน (มีทางได้หัวใจคืนด้วยการทบทวน) (P5)
- R5 ซิงก์ความคืบหน้าข้ามเครื่อง
- R6 ข้อสอบแนว TOEIC Part 5/6 เพิ่มเติมในทุกบท
- R7 ภาษาไทยอ่านง่าย: ฟอนต์รองรับไทย, line-height สูง, ไม่มีตัวอักษรตกหล่น

## 7. สมมติฐานที่ต้องพิสูจน์
| # | สมมติฐาน | วิธีพิสูจน์ | เกณฑ์ผ่าน |
|---|-----------|-------------|-----------|
| H1 | ผู้ใช้เริ่ม lesson แรกได้ภายใน 10 วินาทีหลังเปิดแอป | usability walkthrough งาน T1 | ≤ 2 แตะ |
| H2 | ผู้ใช้เข้าใจเหตุผลจากแถบเฉลยโดยไม่ต้องเปิดสรุป | อ่านเฉลย 10 ข้อแล้วอธิบายกฎได้ | ≥ 8/10 |
| H3 | หัวใจไม่ทำให้รู้สึกถูกลงโทษจนเลิก | สังเกตตอนหัวใจหมด | หาทางทบทวนเพื่อได้หัวใจคืนเองได้ |
| H4 | ผู้ใช้ซิงก์ข้ามเครื่องได้เองโดยอ่านคำแนะนำในแอป | งาน T5 | สำเร็จโดยไม่ต้องช่วย |

## 8. แผน Usability test (heuristic walkthrough — ผู้พัฒนาทดสอบด้วย Playwright + ตรวจด้วยตา)
| งาน | ขั้นตอน | สิ่งที่วัด |
|-----|---------|-----------|
| T1 เริ่มเรียน | เปิดแอปครั้งแรก → เริ่ม lesson แรกของบท 1 | จำนวนแตะ, มีทางเดียวที่ชัด |
| T2 ตอบผิดและเข้าใจ | ตอบผิด 1 ข้อ → อ่านเฉลย → ดูสรุปกฎ → กลับมาทำต่อ | เฉลยแสดงเหตุผล, ไม่หลุดออกจาก lesson |
| T3 ทบทวน | ไปเมนูทบทวน → ทำข้อที่ผิด | ข้อผิดปรากฏครบ |
| T4 ใช้คีย์บอร์ดล้วน | ทำ lesson ด้วย Tab / 1–4 / Enter / Esc | ทำได้ครบ, เห็น focus ตลอด |
| T5 ซิงก์ | สร้างรหัส → ล้างข้อมูล → วางรหัส | ความคืบหน้ากลับมาครบ |

Heuristics ที่ใช้ประเมิน: Nielsen 10 ข้อ (โดยเฉพาะ visibility of system status, error recovery, consistency, recognition rather than recall).
